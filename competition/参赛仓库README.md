# 参赛仓库 README（AtomGit 提交结构）

> 提交截止前，在 AtomGit 建以"队伍名"命名的仓库，按下面结构整理。
> 提交入口以赛事官方页面要求为准。

---

## 仓库结构

```text
AIRouter-比赛提交/
├── README.md                  ← 本说明 + 作品一句话简介 + 演示链接
├── 作品介绍.md                 ← 作品介绍文档（已备，补充落地数据）
├── 评审PPT.pdf                 ← PPT 大纲成稿后导出
├── 演示视频/
│   └── demo-5min.mp4           ← 3~5 分钟真机演示
├── 截图/
│   ├── 01-连接管理.png
│   ├── 02-设备激活.png
│   ├── 03-会话列表.png
│   ├── 04-对话页.png
│   └── 05-多设备适配.png
├── 上架证明/
│   ├── appgallery-链接与截图.png
│   ├── 版权证书.pdf            ← 软著/电子版权证书
│   └── 隐私政策.pdf
├── source/                     ← 完整源码（当前仓库内容，剥离 secrets）
│   ├── entry/                  ← HarmonyOS App（ArkTS）
│   ├── gateway/                ← Node.js Gateway
│   ├── docs/                   ← 设计/部署文档
│   └── scripts/                ← 部署脚本
└── release/
    └── airouter-release.hap    ← Release 构建产物 + 安装说明
```

---

## 提交前检查清单

- [ ] 源码仓库中**无私钥/证书私钥**（`build-profile.json5`、`cert/`、`*.key.pem` 不入库）
- [ ] `README.md` 写清：运行环境、部署步骤（指向 docs/deploy.md）、测试方法
- [ ] 视频 ≤ 5 分钟，含真实服务器连接过程
- [ ] 截图清晰，含手机/平板两种尺寸（如有多设备）
- [ ] 上架证明齐备（链接/截图/进度）
- [ ] 用 Git tag 标记参赛版本（如 `comp-2026`）

---

## 命名建议
- 仓库名：`AIRouter` 或队伍名（官方要求"以参赛队伍名称命名"）
- 作品名建议与版权证书一致：`AIRouter`

## 提交动作（截止前）
1. AtomGit 建仓库 → 上传全部材料
2. 赛事页点"提交作品"，填作品名称、作品介绍、仓库链接/附件
3. 提前 2~3 天提交，截图留档
